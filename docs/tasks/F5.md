# F5 — deterministic encounter setup and synchronous local adapter

Size small; status PASS. F4 dependency reviewed PASS. Independent source/contract review PASS on a2673fa90e929eee410da3a88aefc8d602d34ddd34b44e232e0b88bc512312f2; parent authorized F6 as a large feature.

Only responsibility: validate/select original encounter configuration, build an immutable request from current authorized party, establish/release one local adapter session per controller and record validated visible sightings atomically. No turn/action/capture/reward settlement.

Configuration: wild { kind: 'wild', candidates: Opponent[] } plus caller draw finite in [0,1), selecting floor(draw * length); trainer { kind: 'trainer', opponents: Opponent[] } with no draw. Nonempty arrays. Opponent exact { monster, health, knownMoves, visible:boolean }; monster/health are complete F1/F2 snapshots. Known moves must match enabled F3 rules/resources/slot limits; without training they must be empty. All candidates validated before selection. Party must be nonempty with at least one currentHP >0; opponent lineup must have at least one nonfainted selected target. Duplicate opponent IDs or overlap with any owned IDs reject. No species/damage/level formulas. Kind preserves wild/trainer distinction; later eligibility rules belong F6.

Request: { kind, party, opponents, moveRules } with explicit monster identity/species/nickname, current/max HP/condition and known move/resource snapshots for both sides. moveRules is enabled immutable rules or null. Adapter receives frozen detached request and owns its own copied temporary state; no callback or durable-write capability is supplied.

Public EncounterSession(initialState, adapter) owns the current immutable durable snapshot during its lifetime. state/revision getters expose accepted state. commit(expectedRevision, nextState) validates and accepts only when idle and revision matches; old computed snapshots cannot silently replace newer state. Caller must use this authority rather than maintain a competing mutable state. Counter overflow rejects. No global state, save generation or remote compatibility promise.

Adapter contract is deliberately synchronous: setup(request) returns { release():undefined }, release idempotent and local. Two runnable controlled adapters use this same contract. Promises are not supported (no async callbacks/generation needed in F5). Runtime rejects Promise/thenable handles and non-undefined release returns. Rejections of unsupported native Promises are observed only to prevent unhandled errors after reporting synchronous TypeError; late values are never adopted and observers have no state-write capability. Adapters must clean partial allocations before setup throws; invalid adapters cannot be promised leak-free cleanup. External adapter side effects cannot be rolled back by core.

Lifecycle phases idle/starting/active/releasing guard overlap/reentrancy. Setup failure leaves durable state/revision unchanged and returns idle. Success commits candidate seen-state and stores active request/handle. Only visible chosen wild opponent or explicitly visible trainer opponents are marked seen, never acquired. begin explicitly enables collection if missing (initial owned species correctly acquired) then records sightings, committing only after synchronous handle validation succeeds. Releasing succeeds to idle without changing durable snapshot; failure retains active handle, blocks new begin and allows retry. release on idle is harmless. No public engine handle exposed. Cancellation is explicit release, not a battle outcome or reward.

Acceptance: same state/config/draw -> same selection/request; boundary draw and malformed/candidate/reference checks; overlap/reentrancy; visible-only seen and no accidental acquired; setup/release failure and retry; stale commit refusal; Promise-adapter rejection/no late core write; two interchangeable local adapters and runnable begin/release example; frozen request and isolated temporary state. Revalidate F1–F4 plus separate typecheck/build/build:types/runtime/type fixtures.

Non-goals: async setup, remote engines, commands/receipts/faulted recovery (F6), battle switching/turn/damage/AI, flee/capture/rewards, growth or save APIs. Synchronous choice keeps this small; do not broaden. Skills: actual v2 gameplay B07/B08 and boundary section; transactions local authority/external rollback limits; review scope. No agents/commit/push/publication.
