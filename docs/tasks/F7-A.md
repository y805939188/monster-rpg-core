Opt-in integration: enableGrowth(state,rules) adds one growth field to ownership with no duplicate monsters. initializeGrowth(state,id,experience=0) explicitly enrolls an existing owner, deriving level/maxHP, clamping absolute currentHP (zero stays zero), triggering learned moves up to that initial level. Existing and newly admitted/captured owners remain valid without enrollment; no level is guessed from HP. Enrolled records contain only instanceId/experience/level; species/identity/HP remain authoritative in owned. External validation checks owner uniqueness, XP/level/cap/maxHP consistency. awardExperience(state,id,amount) is an atomic primitive, not a battle reward receipt: positive/zero safe integer, bounded addition, discard excess at cap, multi-level gain. Each call is a new award; exactly-once terminal lineage belongs to F7-B. Trigger source-species learnset for crossed levels in deterministic order using F3 requestLearning (known/pending candidates skipped). Old resources remain unchanged because move rules/maxima are unchanged; new moves use their existing full-resource/null initialization. No species-specific move maxima are invented.

Level evolution offers a stable FIFO choice with choiceId, instanceId, fromSpeciesId, toSpeciesId and required level. One per target. It is offered on enrollment or crossing its threshold; decline consumes it and does not reoffer on later gains for the same species. Resolve only head, exact target/candidate and accept/decline; repeats/old/future reject. Evolution queue and existing learning queue have separate explicit namespaces; all pending learning resolves before an evolution choice. New awards/enrollment/item evolution wait until both queues are clear so no already-committed choice gets silently replaced. This is one deterministic choice sequence, not concurrent choice processing.

Accept evolution retains individual ID/nickname/XP/level/party/inventory except successful item debit, changes species/maxHP with absolute HP clamped, preserves condition and known resources, records acquired+seen, triggers target-species learnset up to current level and eligible next level evolution. Acyclic content prevents looping. Existing source moves may remain known. Item evolution is immediate evolveWithItem(state,id,itemId), matching eligible rule and stock; debit exactly one only on fully valid success, repeated call cannot reapply the same edge on the returned evolved state. Each invocation is a new item action; same-item A -> B -> C successive edges are valid distinct actions, not broad replay idempotence. No equipment/arbitrary effect DSL. ItemEffect union gains evolution; earlier medicine/capture calls retain meaning.
