# F6-A — synchronous command/checkpoint/fault boundary

Status PASS. Independent revision-2 re-review accepted; execution evidence remains implementer-owned. Substep of authorized LARGE F6; A PASS is not F6 DONE. Stop REVIEWING before dependent F6-B.

Preserve F5 begin/release adapters; optional synchronous handle.execute(command) supports A actions. Missing capability rejects before dispatch. New command contains generation (runtime session identity), monotonic commandId (not reused across sessions), source revision, action and last accepted checkpoint. One synchronous execution at a time; reentrant act/commit/settlement/release reject. First living party member is initially active. activeRequest remains the immutable F5 initial request; checkpoint getter exposes latest accepted battle state.

Action exact shapes: move { kind, actorId, moveId, targetId } and switch { kind, actorId, targetId }. Actor must be current active party identity. Move requires actor alive, known move with positive finite resource (or none), and live opponent target. Costs exactly one finite unit in the adapter-reported snapshot; core does not debit again. Switch target is a different live own-party member. A plain switch preserves existing wounds/resources without reconstructing either individual. The trusted engine may report retaliation/end-turn effects on HP, condition and resources, including terminal outcomes. Core validates their bounds, unchanged identities/maxHP/move definitions, selected activeId and normal outcome consistency; it does not implement turn effects. Preflight errors allocate no command and do not fault.

Confirmation exact shape: { generation, commandId, revision, outcome, checkpoint }. Correlation equals dispatched request. Checkpoint contains complete ordered party/opponents combatants plus activeId. All IDs/species/nicknames/maxHP/known move identities remain unchanged; numeric HP/condition/resources are validated. Core trusts adapter for legal damage/temp effects; it does not verify a damage formula. Selected move's finite count must equal prior minus one; no-resource stays null. Other reported permanent fields may change only within validated existing definitions. Outcome continue requires both sides retain living members; victory requires opponents all fainted and some party living; defeat requires party all fainted. Double KO classified defeat. Move keeps activeId; a fainted actor may switch next if team still lives.

On valid continue: replace party permanent HP/resources in durable owned/training checkpoint once; preserve other owners, inventory/collection/choices. On valid victory/defeat: compute and validate next state, release adapter synchronously, then commit; no reward/penalty/growth. Release failure yields fault without terminal commit or success receipt. Opponent state stays runtime-only. All results are detached/frozen.

Retain only last accepted confirmation+receipt and current small fault {generation,commandId,revision,reason}. No event log or raw malformed payload retained. confirm(input) is replay-only: exact latest confirmation (object-key order irrelevant) returns already_applied; conflict, old consumed, future or stale-generation input rejects without engine execution. No public uncommitted-confirmation retry path. New successful begin invalidates old-session replay while command IDs remain monotonic.

Once adapter invoked, exception/invalid result/terminal release failure -> faulted. No new act/begin/commit, no automatic engine retry; prior accepted costs/checkpoint remain. abandonFaultedEncounter retries only local release; success clears runtime session/fault and returns retained checkpoint, without victory/defeat/reward. Failed abandon release retains fault/handle and blocks overlap. Exact prior accepted replay may be acknowledged while faulted but never unblocks it. F5 ordinary release remains cancellation of a healthy active session; a thrown/non-undefined release enters cleanup_failed, retaining the handle and checkpoint. Only idempotent release retry can clear this state; act/begin/commit remain blocked. Exact latest confirmation acknowledgment cannot unblock it. Faulted command sessions still require explicit abandon. Adapters must have idempotent local release. External-engine rollback is not promised.

Acceptance: finite/no-resource move checkpoints, preserved switch state, final victory/defeat without rewards, invalid/forged checkpoints and numeric/identity/correlation fields, bounded exact replay/conflict/old/future, reentrancy, prior accepted cost survives next fault/abandon, terminal/abandon release failure, stale session/Promise result rejection, two local implementations and runnable A example. Full F1–F5 regression/type suites.
