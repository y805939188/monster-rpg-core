# 第一版玩法验收基线 v2

状态：设计提案，待用户确认；替代启动报告v1的过窄闭环。核心参照宝可梦基础玩法，使用原创内容；Vite已由用户明确要求采用。以下完成标准是产品设计，不是原游戏内部实现描述。

## 最低能力矩阵

| ID | 玩家可观察行为 | 核心与规则职责 | 适配器职责 | 最低验收 |
|---|---|---|---|---|
| B01 | 同物种两个不同个体 | ID、昵称、经验与独立状态；物种定义不可变；个体ID稳定，speciesId仅经合法进化变更 | 只接收副本 | 改一只不影响另一只；拒绝未知物种/重复ID |
| B02 | 得经验、跨等级成长 | 可替换曲线/属性规则、等级上限 | 报告合法结束与参与者 | 一次奖励跨多级、封顶、重复奖励无额外效果 |
| B03 | 学招、拒绝、替换 | 学习表、槽位容量、待选事件 | 根据当前招式构建合法行动 | 未满新增、满额替换/拒绝、多次学习顺序明确 |
| B04 | 有限招式资源 | PP式示例与无PP替换配置 | 消耗与行动可用性 | 不为负、零使用次数拒绝、治疗恢复；核心不硬编码PP |
| B05 | 队伍和仓库管理 | 唯一持有、队伍子集、容量/溢出策略 | 战斗快照中的出战名单 | 调序、存取原子性、队伍满入存储、总容量满不丢个体；战内换人验证合法队友/资格并保留个体HP与资源 |
| B06 | 受伤、濒死与治疗 | 长期HP/持久状态/资源；治疗规则 | 战斗临时HP/状态及同步 | 回复/复活/清状态，不改物种/归属；重复治疗安全 |
| B07 | 野外遭遇 | 可复现候选生成、会话生命周期 | 提供合法行动及受控结果 | 同输入遇同配置、拒绝重叠会话 |
| B08 | 训练师挑战 | 配置队伍/奖励、完成标识 | 战斗过程 | 胜利奖励一次，失败无胜利奖励 |
| B09 | 逃跑 | 允许条件/成功规则 | 回合时机与继续 | 野外失败后继续、成功结束；示例训练师禁止逃跑 |
| B10 | 战斗中捕捉 | 道具消耗、合法目标、持有与图鉴一次提交 | 活跃目标与捕捉确认/移除/终止 | 失败扣道具并继续；成功仅一只；训练师目标拒绝；captured不同于victory |
| B11 | 背包与道具 | 栈计数、目标/效果规则、外部治疗 | 战内道具时机 | 不足/非法目标拒绝，成功一次消耗，no-effect策略明确 |
| B12 | 基础进化 | 等级与道具两种规则，身份保持、属性协调 | 本期不负责进化 | 等级进化可拒绝；道具进化成功才扣道具；新物种属性合法 |
| B13 | 见过和获得记录 | 单调seen/acquired，不等于当前持有 | 报告遭遇方可见信息 | 遭遇仅seen，捕捉两者，进化新物种获得，不因离队抹除 |
| B14 | 战败后继续 | 惩罚/恢复策略、宿主恢复请求 | defeat一次结束 | 无奖励泄漏、可恢复游戏；核心不操作地图 |
| B15 | 保存与继续 | 版本化状态和校验，保留待选择事件 | 本期不序列化活跃引擎 | 完整往返、非法存档拒绝、战斗中保存明确报不支持 |

## 职责和保证

核心只管理长期状态与受校验事务，不实现伤害公式/AI/完整回合。适配器是可信的战果生产者，不是防作弊验证目标。先验证、计算、再提交，失败不半改核心状态。外部引擎已经推进时不能承诺整体回滚：保留同请求ID和确认结果，暂停新的命令，在受支持的重放/恢复边界解决差异；没有能力时明确报不支持。

一次只处理一个会话中的一个未确认命令；本期不并行提交行动。捕捉/战内用药请求按会话和命令ID去重，成功提交记录同时包含核心道具与归属变化。不能让适配器和核心各扣一次道具。容量不足在发起不可逆捕捉前检查；意外失配必须显式失败且可追踪，不丢怪兽。

保存仅在无活跃战斗时允许；允许保存待学招/进化选择。恢复后废弃旧运行会话的异步回调。历史存档回滚后不承诺全局exactly-once。文件可靠写入属于宿主；内存原子状态转换不等于磁盘事务。

## 原创验收路线

伙伴与少量道具开局 → 野外发现物种并登记seen → 一次招式与资源消耗 → 首次捕捉失败后继续 → 第二次成功并命名/登记acquired → 队伍/仓库调度及满队捕捉 → 训练师禁止逃跑/捕捉，允许换人及治疗道具 → 战斗胜利奖励一次 → 跨级成长、满槽学招选择、基础进化 → 另一只道具进化 → 野外逃跑与训练师战败分支 → 治疗 → 保存重载 → 再次遭遇。全程通过公共API和受控适配器，不把脚本称为真实战斗引擎。

Node24.19.0、npm11.9.0、TypeScript7.0.2、Vite8.3.1（官方registry元数据已读，实际安装与兼容烟测尚待F0）。Vite的Node要求^20.19.0或>=22.12.0，当前Node满足。Vite Library Mode产出JS；tsc独立严格类型检查和声明生成；Node测试验证产物。Vite仅开发依赖，不要求HTML/DOM/React，不引入多包平台。

## v2 审查后补充契约

每个会话同时只有一个in-flight命令，单调命令编号，最多保留最近已接受回执和当前失败确认。旧已消耗命令明确拒绝，无需保存全历史结果。

引擎已推进但核心拒绝确认时，将运行会话标记faulted，禁止继续发行动。格式/引用/关联/数值/规则校验失败均不自动重试引擎，也不自动重试同一非法确认。保留失败ID及经脱敏的诊断，不半提交该动作。由显式abandonFaultedEncounter终止该会话，丢弃测试引擎实例，回到最近一次已提交核心检查点；这不是回滚外部引擎。先前已确认捕捉失败的道具消耗/HP变化保留，本次非法捕捉不发个体/奖励也不扣第二次道具。中止不是victory或正常defeat，不应用胜利奖励。适配器本期必须支持本地会话释放；无法释放的远程持久引擎不宣称兼容。合法已提交确认重放只返回already_applied；合法确认已计算但宿主尚未提交时，只有原revision和运行代次仍匹配才允许重新提交同一数据，不再向引擎发行动。

长期状态在每次已确认动作后接受经过校验的检查点；战斗临时状态仍由引擎持有，核心不同时独立改变它。捕捉、胜利、逃跑、战败均采用该动作最终合法快照，再应用对应核心规则；未报告字段不能猜测。捕获个体保留合法目标当前HP和声明的持久状态，临时战斗状态丢弃。成长/进化不自动治疗：保持绝对当前HP并钳制到新上限，0HP仍为0；保留招式资源并钳制新上限，新学招式按内容初始资源给值，无PP配置不虚构PP。规则将来可替换，但必须有对应测试。

待学习/进化选择保存 choiceId、个体ID、候选招式/物种、排序和未解决状态。恢复校验所有引用、资格/版本及唯一顺序；解决选择恰好一次，重复提交不能替换另一个招式或重复奖励。恢复旧存档会恢复它当时未解决选择，不承诺回滚去重。新运行代次拒绝恢复前异步回调；代次不序列化。
